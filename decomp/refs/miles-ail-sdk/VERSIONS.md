# Miles AIL / MSS reference headers — version index & PS.EXE pin

This directory collects every real, reachable Miles **AIL.H / MSS / AIL32**
header across the product's history, plus the official RAD Game Tools
development-history changelog.  These are **reference evidence only** —
the Caesar II decompilation does **not** build against any of them; the
decomp links the real AIL binary shipped in PS.EXE (the byte oracle).

The goal is to pin, as precisely as an open-source / archival search
allows, which Miles AIL version Impressions linked into Caesar II
PS.EXE, and to hold the API header surface for cross-checking our
`decomp/include/ail.h` prototypes.

## PS.EXE pin — AIL **3.03 (base, 1995-06-18)**

`data/PS.EXE` contains the standalone string:

```
03.03 00  "Audio Interface Library application usage script generated by AIL V%s"
```

i.e. `AIL_VERSION` = `"3.03"` (null-terminated), immediately preceding
the AIL usage-script banner whose `%s` is filled by that version at
runtime.  Cross-referenced against the preserved RAD changelog
(`dev-history/version-timeline.txt`):

| version   | RAD date      | notes |
|-----------|---------------|-------|
| 3.02 → 3.03  | **1995-06-18** | ← **PS.EXE links this (base 3.03)** |
| 3.03 → 3.03a | 1995-06-25    | "has been fixed" (MS-DOS only) |
| 3.03a → 3.03b| 1995-06-29    | |
| 3.03b → 3.03c| 1995-11-07    | |
| 3.03c → 3.03d| 1995-11-22    | last AIL (pre-RAD-sale rename) |
| 3.03d → 3.04a| 1996-02-04    | first "Miles Sound System" build |

PS reports `3.03` with no suffix, so the linked AIL library is the **base
3.03 release (1995-06-18)** — not 3.03a–3.03d.  All three Caesar II DOS
builds (`dbg-1996-04`, `rel-1995-10`, `rel-1995-09`) post-date 3.03 and the
3.03a–d series, yet print `3.03` → Impressions licensed + linked base 3.03
once and never bumped the AIL library across the builds.

`3.03` of 9-Jan-95 in the mig_src header comment (below) is the
**header-revision** date (when the `.H` was edited), not the binary ship
date; the binary product version string is what PS prints.

### Closest-available header oracle = `AIL.H` (3.6B)

No genuine AIL **3.03** header is publicly available.  The v3.x line was
**never open-sourced** — John Miles only ever OSS-released AIL v2.14
(+ AIL/32 v1.05, "as of May 26, 2000, open-source freeware").  Searches of
GitHub, archive.org (incl. the Dave Lowe "Miles Sound System SDK 1 of 3
1996.10.22" floppy, which contained only `SETUP.EXE` — disks 2/3 absent),
ke5fx.com, VGMPF, and VOGONS all confirm the 3.x headers do not circulate.

The **3.6B `AIL.H`** (1997) is therefore our best authentic header reference.
The 3.50/3.6 milestones only *added* functions; the prototypes for the
calls PS uses (`_AIL_install_DIG_INI`, `_AIL_install_MDI_INI`,
`_AIL_init_sequence`, `_AIL_start_sequence`, `_AIL_resume_sequence`,
`_AIL_sequence_status`, `_AIL_register_trigger_callback`, …) are
identical to the 3.03 surface.  The `CookiePLMonster/VBdec` `mss.h`
header notes confirm the 3.02→3.03 delta was purely additive:
*"Version 1.00 of 15-Feb-95: Initial, derived from AIL.H V3.02 /
1.01 of 19-Jun-95: Added various functions for V3.03 release."*

## Re-deriving the exact AIL prototypes PS compiled against

The authoritative prototype source is not any header file but the **actual
AIL binary linked into PS.EXE** — it is the decomp's byte oracle and it
defines the real calling convention / arg counts Impressions called.
Grepping PS.EXE for the `AIL_*` API trace strings (`AIL_startup()`,
`AIL_init_sequence(0x%X,0x%X,%d)`, …) plus the external-symbol import table
(`_AIL_*`, Watcom-decorated) gives the exact surface; see the cross-build
`c2 disasm` / `c2 xrefs` tooling.
