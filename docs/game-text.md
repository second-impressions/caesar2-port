# Game text

The port compiles the game's text into the executable, in every language it
knows, as gettext files under `po/`. The disc's `C2.ENG` and `HELP.ENG` are
read only to detect their language. This replaces the earlier runtime
adaptation to the shipped files' revisions (`docs/text-asset-versions.md`,
now removed): the recovered 1996 engine always sees the 1996 layout.

## Files

| File | Content |
|---|---|
| `po/c2.pot` | the template: English text from the 1996 DOS release, `msgstr` empty |
| `po/de.po` | German, from the 1996 rerelease |
| `po/fr.po` | French, from the 1995 release plus the port's own translations of the strings the 1996 engine added |

Adding a language is adding one `po/<tag>.po`; CMake globs the directory.
The template's `msgid` is the English text; a translation's empty or
`fuzzy` `msgstr` falls back to it, as in gettext, so partial translations
run.

Two header fields are the port's own:

- `X-C2-Name`: the language's native name, shown in the launchers;
- `X-C2-Detect`: the first string of the language's original `C2.ENG` (its
  File menu: "File", "Datei", "Fichier"). The game data is recognised by it.

## Keys

`msgctxt` is the engine's own address of a string:

- `0x2f/3` — `C2.ENG` string group `0x2f`, string 3, exactly as the
  recovered source spells `font_list(0x2f, 3, …)`. `#:` references name
  the call sites the tool could find literally.
- `help/1234/0` — `HELP.ENG` page 1234, string 0 (the title); `/1` is the
  body. A page that shares another page's text has the reference `msgid`
  `"@1234"` in each slot. A translation may keep the reference or replace
  it with text: the German help uses spare pages this way for chapters
  that ran long, and links pages differently as a result.

Help bodies use `\n` for the engine's `$` line break. `#12text#` is a link
to page 12 and must survive translation. The engine reads a help page into
2000 bytes and the whole `C2.ENG` into 40 000; `tools/c2-text.py check`
enforces both, and a duplicate or unknown key, before a translation is
merged.

## Encoding

The bitmap font is indexed by CP437, so the `.po` files are UTF-8 and the
runtime transcodes. Not every code point has a glyph: the uppercase
umlauts draw as the bare letter, `«»` and `&` draw as nothing. `check -v`
lists what a translation uses that the font cannot draw; the shipped files
do this themselves in a few places, so it is a warning.

## Runtime

`src/platform/common/c2_port_text.c` parses the selected language's file
at the first `readfile("c2.eng")`, rebuilds the 1996 `Textfile` layout
(147 groups, groups 117 and 118 sharing 116's payload and 120 sharing
119's) straight into `text_buffer`, and rebuilds a `Helpfile` that
`readfile("help.eng", …, offset)` then serves by offset. The help page
records — illustration and voice file names, sprite ids, widths — are
language-neutral and compiled in from the 1996 English file
(`c2_port_help_records.inc`, generated by `c2-text.py records`).

No recovered source changes: `readfile()` in `c2_port_compat.c` is the one
hook, and the engine keeps addressing text by `(group, index)`.

The language is `--language TAG`, else the launcher's choice
(`launcher.ini` `language=`; the web page keeps it in local storage), else
the one detected from the game data, else English. Speech, illustrations
and movies remain those of the game data; only the text is chosen.

## Tooling

`tools/c2-text.py` is a developer tool and never part of the build:

```bash
# template and translations from original files (done once; results committed)
tools/c2-text.py pot --c2 C2.ENG --help-file HELP.ENG -o po/c2.pot
tools/c2-text.py extract --c2 C2.ENG --help-file HELP.ENG --pot po/c2.pot \
    --lang de --name Deutsch -o po/de.po
# validate before merging
tools/c2-text.py check --pot po/c2.pot po/*.po
# the reference compiler; tests compare the C runtime's output with it
tools/c2-text.py compile po/de.po --c2 out.eng --help-out out.hlp
tools/c2-text.py compare original/HELP.ENG out.hlp
```

`extract` knows the shipped files' faults. The French `C2.ENG` split
several strings with a NUL instead of a space and merged two others, so
every later index in four groups pointed at the wrong text in the shipped
game; the 1995 files have no battle icon tips at all (groups `0x74`–`0x78`
alias one Senate letter there); two French help pages carry title and body
in one string and two split the body in two. The fixups restore the
engine's segmentation. The four `0x92` bytes the English help used for
apostrophes are corrected in the template.

Where an original string exists in more than one revision, the later one
is used: the 1996 DOS text over the 1995 text, and over the Windows text,
whose differences are cosmetic. The one exception is the German Help menu,
which keeps the 1995 `?`: the rerelease's `Hilfe` runs into the date.

`tests/test_c2_text.py` validates every bundled file and, when the debug
build is present, compares the C runtime's `C2.ENG` and `HELP.ENG` for
every language byte for byte with the tool's. The English `C2.ENG` is
also byte-identical to the 1996 original; the help files are identical in
every page and record (the originals stored a few unreferenced bytes).

## Contributing a translation

Any gettext editor or platform (Poedit, Weblate, Crowdin) works with these
files as they are. Run `tools/c2-text.py check --pot po/c2.pot po/xx.po -v`
before opening a pull request: it reports what will not fit and what the
font cannot draw.
